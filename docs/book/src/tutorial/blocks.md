# Блоки: `domain` и `component`

Конфиг редко бывает плоским. В Aura структуру задают **блоки**. Их главное
отличие от обычного вложенного объекта (`key:` … `end`) — блок открывает
**область видимости**: внутри разрешены `=`, `shadow`, `assert`, `def` и
вложенные блоки, тогда как обычный объект принимает только свойства.

Блоков два, и различаются они ровно одним: `component` дополнительно добавляет
в тело поле `name` со значением метки.

| Форма | Что даёт | Где применяют |
| --- | --- | --- |
| `domain "prod" ... end` | `"prod": {…}` — метка как ключ | секции, окружения |
| `component "prod" ... end` | то же + поле `"name": "prod"` внутри | элементы списков (обычно из `map`) |

## `domain` — именованная секция

Метка блока становится ключом объекта в выводе:

```ruby
domain "prod"
  replicas: 3
  region:   "eu-central"
end
```

```json
{
  "prod": {
    "replicas": 3,
    "region": "eu-central"
  }
}
```

Внутри блока действуют обычные правила `=` против `:`
(см. [Вычисления и вывод](bindings.md)): `key:` попадает в JSON, `=` остаётся
приватным вычислением.

## `component` — блок, который знает своё имя

`component` — это тот же блок, что и `domain`, плюс автоматическое поле
`name` со значением метки. На верхнем уровне разница видна прямо:

```ruby
component "solo"
  x: 1
end
```

```json
{ "solo": { "name": "solo", "x": 1 } }
```

Главная его роль — элементы списков. Внутри `map` блок становится **значением**
лямбды, внешнего ключа нет, и остаётся объект со своим `name`:

```ruby
services: ["api", "web"].map (n, i) ->
  component n
    port: 8000 + i
  end
end
```

```json
{
  "services": [
    { "name": "api", "port": 8000 },
    { "name": "web", "port": 8001 }
  ]
}
```

Метка `component` может быть любым выражением (здесь — параметр лямбды `n`),
поэтому шаблон элемента пишется один раз вместо копипасты.

Внутри `map` блок нужен ещё и потому, что тело лямбды принимает только
свойства: приватные вычисления (`=`) допустимы лишь внутри блока.

```ruby
svcs: ["api"].map (n, i) ->
  component n
    base = 8000 # `=` работает только внутри блока
    port: base + i
  end
end
```

## Область видимости

Блок открывает новую область. Внешние переменные видны, но затенение требует
явного `shadow` (D7):

```ruby
port = 80

domain "prod"
  shadow port = 443 # без `shadow` — E0302
  listen: port      # 443
end

fallback: port # 80 — снаружи ничего не изменилось
```

Это прямой ответ на вопрос «почему в проде другой порт»: перекрытие значения
всегда видно в коде.

## Вложенность

Блоки вкладываются друг в друга, а простые вложенные объекты создаются обычным
`key:` с переводом строки (отдельного ключевого слова не нужно):

```ruby
domain "prod"
  security: # вложенный объект
    tls:     true
    ciphers: ["TLS_AES_256"]
  end

  domain "eu" # вложенный блок
    region: "frankfurt"
  end
end
```

```json
{
  "prod": {
    "security": { "tls": true, "ciphers": ["TLS_AES_256"] },
    "eu": { "region": "frankfurt" }
  }
}
```

Обратите внимание: `domain "eu"` и `security:` дают в JSON одинаковую форму —
вложенный объект. Разница не в выводе, а в том, что можно написать внутри:
в `security:` допустимы только свойства, в `domain "eu"` — ещё и `=`, `shadow`,
`assert`, `def`.

## Что выбрать

- Просто **вложенные данные** → `key:` … `end`. Самая простая форма, свойства.
- Нужны внутри **вычисления** (`=`, `shadow`, `assert`, `def`) → `domain`.
- Нужен **список объектов, каждый со своим `name`** → `component` внутри `map`.

Коротко: `key:` — данные, `domain` — данные плюс вычисления, `component` —
то же, что `domain`, плюс автоматическое поле `name`.
